# Example Compiled Hook Mod

A hook in two parts, in one `apkJarPatch` on `services.jar`:
- the Java class `hooks/smali_classes2/org/ide/lti/example/hook/ExampleHook.java`, compiled into smali by
  `compileModPayload` (`files/smali_classes2/…`) and added to the jar by `addSmali(File("files"))`;
- a `method(…)` edit that calls it: in `InstallPackageHelper.scanSystemPackageLI`, before the call to
  `ScanPackageUtils.collectCertificatesLI`, `@{setting}` captures the call's first register and passes it to
  `ExampleHook.onCollectCertificates`. Checked against PQ84P01's stock services.jar.

`plan.json` shows the method edit as it is serialized. A plan generated from `Mod.kt` also holds the compiled
class, as an `addFile` edit per smali file.

## Payload Configuration

`payload.json` names the target firmware's jars and APKs the hooks are compiled against, so a hook calls hidden
framework APIs exactly as that firmware has them (copy them from the firmware, e.g. `system/framework/framework.jar`):
```json
{
  "minRuntimeApi": 34,
  "firmware": ["/path/to/firmware/framework.jar", "/path/to/firmware/services.jar"]
}
```

Hooks are Java, not Kotlin: Kotlin classes need the Kotlin runtime, and `kotlin.*` classes added to framework.jar
would shadow every app's own Kotlin.

## Compiling the hooks

```bash
./gradlew :sdk:patch-mod-hooks:compileModPayload -PmodProject=sdk/patch-mod/examples/compiled-hook
```

Each folder under `hooks/` is a smali folder of the target component (`smali`, `smali_classes2`, …). The firmware
files are converted to signatures-only jars (dex2jar), then javac, d8 and baksmali run in-process and write
`files/<smali folder>/…/*.smali`. Every generated file starts with a `# Generated by HookCompiler` line and is
replaced on the next compile.
